# 检索路由

本文件定义**怎么选信源、怎么构造双语查询、怎么判断动态时效与证据等级，以及何时启动能力发现旁路**。

## 按任务选择首选信源

除 `Deep` 模式或用户明确指定平台外，按任务类型从下表选 **2–4 个互补信源**（例如 1 个一手官方/项目源 + 1–2 个中文/英文实操社区 + 1 个视频或论文源），避免对 21 个站点做无差别通扫。

| 任务类型 | 首选信源（挑 2–4 个） | 补充信源（按需补查） | 重点获取的证据 |
| --- | --- | --- | --- |
| **AI / Agent / MCP / 模型选型** | `github` · `x` · `linux-do` · `huggingface` | `hacker-news` · `arxiv` · `youtube` | 最新版本能力、真实踩坑、许可与硬件成本、可复现配置 |
| **软件选型 / 找平替 / 效率工作流** | `alternativeto` · `v2ex` · `sspai` · `reddit` | `zhihu` · `xiaohongshu` · `hacker-news` | 候选清单、迁移成本、定价变化、平台与本地化约束 |
| **工程架构 / 后端 / 排障与兼容性** | `github` · `stackoverflow` · `lobsters` · `juejin` | `wechat-mp` · `hacker-news` · `nodeseek` | 精确报错原因、架构权衡、生产反例、版本升级差异 |
| **学术方法 / 科研绘图与论文溯源** | `arxiv` · `github` · `reddit` · `xiaohongshu` | `zhihu` · `bilibili` · `youtube` · `wikimedia-commons` | 论文原图与图注、作者代码/脚本、期刊排版与后期组合 |
| **部署运维 / 国内网络与自托管** | `nodeseek` · `linux-do` · `v2ex` · `github` | `wechat-mp` · `tieba` | 国内可用性、代理/字体/镜像限制、自托管配置与费用 |
| **可复用图片、矢量图与视频教程** | `wikimedia-commons` · `bilibili` · `youtube` · `github` | `xiaohongshu` · `arxiv` | 可编辑源文件、单图许可与署名、带时间戳的操作步骤 |

多平台深度调研（`Deep` 模式）可按子问题为纳入范围的平台分配检索重点与投入权重；权重决定补查深度，而非单条证据的可信度。新发现改变优先级时，记录调整依据。

## 不同运行环境的检索入口

切换运行环境时，先检查当前可用的工具、网络与会话，按 [信源访问手册](platform-access-playbook.md) 优先走公开免登录路径。

| 当前环境能力 | 推荐用法 |
| --- | --- |
| **有公开 API / CLI（如 `gh`、curl/HTTP）** | 优先覆盖 `github`、`hacker-news`、`arxiv`、`huggingface`、`stackoverflow`、`lobsters`、`wikimedia-commons` 等免登录信源，速度快且字段精确 |
| **无浏览器，有网页搜索 + 原文抓取** | 搜索工具发现候选，抓取工具读回原文；遇到反爬/登录墙或仅能看到摘要时，尝试公开降级入口或记录缺口 |
| **有独立浏览器（无用户登录态）** | 用于动态渲染页、公开媒体与页面截图；遇强登录墙时交接，不绕过认证或人机验证 |
| **有用户浏览器会话（含登录态）** | 用于用户指定浏览器及需登录的 `xiaohongshu`、`x`、部分 `zhihu`/`linux-do` 板块，以及需肉眼核对的图片/评论 |
| **仅能读取本地文件或用户材料** | 用已有材料完成整理、去重与决策分析，并给出最小化的待补查清单交接给有网一方 |

### 登录交接与跨 Agent 采集规范

- **登录交接**：必需正文或评论被登录页挡住时，中途暂停并请用户在可用会话中登录（浏览器支持交接时保留原标签页）；用户返回后从同一查询继续核验。公开正文已可见时直接读取。用户放弃该平台时，保留覆盖缺口。
- **跨方采集交接**：需要另一位 Agent 或用户补采时，只列出当前任务必需的：目标信源、查询词、需要读回的证据层级与访问条件。回传须包含：原始链接或 ID、获取时间、有效日期、正文/文件定位点与访问状态。

## 按社区习惯构造双语查询

- **中文社区**：用国内真实表达描述场景和限制，保留工具英文原名。
  - 找实操：`实测`、`教程`、`怎么用`、`踩坑`、`避坑`、`复盘`
  - 找选型：`求推荐`、`有没有人用过`、`平替`、`对比`、`迁移`
  - 找本地约束：`国内使用`、`自托管`、`中文字体`、`私有化`
  - 示例：`知识库迁移 附件丢失 踩坑` → `linux-do` / `v2ex` / `juejin`
- **英文社区**：用领域惯用术语加具体产物、版本、错误信息或限制词。
  - 找体验与权衡：`anyone using`、`how do you`、`tradeoffs`、`gotchas`、`limitations`、`migration`
  - 找可复现材料：`case study`、`workflow`、`source files`、`benchmark`、`postmortem`
  - 示例：`knowledge base migration preserve attachments broken links` → `reddit` / `hacker-news` / `github`
- **双语交叉**：对同一子问题分别构造中英文查询，互查工具原名、生态差异和地区限定条件；在结论中标明哪些做法依赖特定地区/环境，哪些有双语独立实证。
- **消歧**：遇到多义词或同名软件/游戏（如贴吧的 `Origin`），必须补充领域消歧词（如 `OriginLab`、`曲线拟合`）。

## 动态时效与证据分级

### 1. 动态滑动时间窗

以执行当天的系统日期 `T` 计算时间窗口，不硬编码固定年份：

- **快迭代领域**（AI、Agent、MCP、模型评测、前端/云原生工具、SaaS 功能与定价）：
  1. **首选窗口（`T - 12 个月` 至今）**：优先用平台“最新”排序、年份/当前版本号或搜索时间算子（如 `after:YYYY-MM-DD` 按 `T - 12 个月` 现算）获取现行实证。
  2. **补充窗口（`T - 24 个月` 至 `T - 12 个月`）**：当首选窗口不足、存在分歧或需追溯演进时扩大到此区间，且涉及当前功能/接口时必须回查官方最新文档或最新 Release。
  3. **历史参考（早于 `T - 24 个月`）**：仅作背景、原始设计动机或对照，不直接作为当前工具选型主依据。
- **慢迭代领域**（经典系统架构、科研统计规范、数学/算法原理、基础协议与期刊投稿指南）：
  - 以“是否仍为现行主流或已被新版本/新规范取代”为准，不机械按发布年份降权。
- **用户覆盖**：用户指定时间区间或特定版本时，严格按用户要求执行。

### 2. 有效日期核验

- 必须回原页核对真实发布日、相关软件版本发布日或有证据的实质更新日。
- 区分：帖子原发时间、高价值评论时间、视频上传日与演示中的软件版本。
- 转载、置顶、最近回复或抓取时间不能冒充原证据日期；原证据沿用其原始有效日期。日期无法核验时标明 `日期待核`。

### 3. 离散证据分级与去重

摒弃无锚点的主观百分制打分，先剔除无关结果，再按**证据可信层级 + 时效窗口**综合排序：

| 等级 | 定义 | 典型来源 | 使用方式 |
| --- | --- | --- | --- |
| **Tier 1（高可信一手）** | 正式规格、源码、论文原件，或附带可复现代码/源文件/成品对比的一手实测 | 官方文档、GitHub 源码/Release、arXiv 原文、Wikimedia 原图许可页、带源文件的完整案例 | 可直接支撑关键结论、规格判断与交付标准 |
| **Tier 2（有效社区实证）** | 明确给出版本、场景、约束、收益与失败条件的亲历帖、高价值评论或演示 | `linux-do` / `v2ex` / `reddit` / `hacker-news` / `lobsters` / `juejin` / `sspai` / `xiaohongshu` 亲测贴与关键回复 | 用于提炼选型取舍、踩坑清单与验收项，尽量双源交叉 |
| **Tier 3（仅作线索）** | 二手转述、未核验日期/版本、仅搜索摘要可见、未看正文/字幕的视频、营销合集 | 转载号、索引片段、仅看了简介的视频、待登录核验的链接 | 只能作为线索或记录在缺口中，不单独作为核心决策依据 |

- **合并与冲突处理**：指向同一原始论文、仓库或公告的多篇社区转述合并为一条主证据；不同来源结论冲突时，逐项比对软件版本、有效日期、运行环境与前提假设。

## 能力发现旁路（按需触发）

默认**直接使用当前环境已有入口**完成检索，不把“找第三方 Skill”当作常规前置步骤。仅在满足以下任一条件时，才启动本旁路：

1. 用户明确要求先寻找、评估或安装某个平台的专用检索 Skill / MCP / CLI；
2. 某**核心必需信源**在当前所有已有入口（含公开降级入口）均无法获取关键证据，且用户确认愿意投入额外轮次评估外部工具。

启动后的最小步骤：
1. 按「信源名 + 具体动作或证据」在 [GitHub](https://github.com/) 或 Skill 目录（如 [skills.sh](https://skills.sh/)）发现候选，将指向同一上游的条目合并去重。
2. 回上游读 `SKILL.md`、README、源码与提交记录，核对覆盖信源、返回的证据层级、依赖和权限范围。
3. **先静态审查、后经用户授权安装与运行**。
4. 角色边界：接入后的专用工具/Skill 担任**信源执行层**（负责抓和读），本 Skill 始终担任**检索编排层**（负责拆题、时效判断、证据分级与缺口汇总）。若候选不可用，回退至可用替代入口并记录缺口。
