# 交付输出模板（Output Contract）

所有检索交付遵循**结论先行、证据分级、缺口透明**三原则。根据任务所选模式（`Quick` / `Standard` / `Deep`）选用对应模板，不遗漏关键定位信息，也不堆砌无用字数。

---

## 1. Quick 模式模板（快速核验 / 已知对象溯源）

```markdown
## 结论
- **核验结果**：<直接给出答案、原始出处或版本结论>
- **适用范围与限制**：<版本、环境或前提条件>

## 一手来源
- [<标题>](<原始链接>) · `Tier 1` · 有效日期：`YYYY-MM-DD` · 读取层级：`原文已读` · 定位：<章节/图号/Issue/代码路径>

## 缺口（如有）
- <若核心原页不可达，写明原因与影响；无缺口可省略本节>
```

---

| 方案 A | ... | ... | ... | Tier 1 / Tier 2 来源编号 |
| 方案 B | ... | ... | ... | Tier 1 / Tier 2 来源编号 |

## 关键踩坑与验收项
- <从社区失败案例和官方限制中提炼的可执行检查项，3–6 条>

## 3. Deep 模式补充模块（深度跨平台调研 / 可复跑沉淀）

```markdown

| --- | --- | --- | --- | --- |
| `github` | ... | `...` | `gh` CLI | 原文已读（3 个仓库、2 条 Issue） |
| `xiaohongshu` | ... | `...` | 浏览器 | 访问受限（需重新登录，留缺口） |

## 后续执行 / 交接建议（可选）
- <若结果要交给下游 Agent 或用户继续实施，列出输入清单、可编辑格式要求与复查入口>
```

---

## 交付自检清单（发送前核对）

- [ ] 结论与对比表在最前，没有先铺陈冗长检索流水账。
- [ ] 每条核心主张都对应至少一条 `原文已读` 的 `Tier 1` 或 `Tier 2` 来源，没有拿 `仅索引可见` 当确定事实。
- [ ] 所有引用均标明了真实有效日期（或明确写 `日期待核`），未将转载/抓取时间当发布日期。
- [ ] 存在冲突结论时，已核对版本、时间或运行环境差异。
- [ ] 登录受限、人机验证或未看视频字幕的情况已在缺口中如实披露。
